## 2. АЙДЕНТИКА, ДИЗАЙН-СИСТЕМА И ВИЗУАЛЬНЫЙ ЯЗЫК HUD/FUI

### 2.1. Канонический знак S и правила брендбука
Визуальным фундаментом бренда является знак **S**, состоящий из двух неразрывных комплементарных частей с центральным синаптическим интерфейсом.

* **Критическое правило (D-003):** Две части буквы S **никогда не должны визуально разрываться или разделяться**.
* **Динамика и анимация:** Движение принадлежит исключительно центральной синаптической зоне и окружающему нейронному/электрическому полю.
* **Принятый цикл анимации:** Медленная непрерывная пульсация; электрические и нейронные точки движутся вдоль эллиптических/круговых линий, огибая форму S; происходящий в центре энергообмен.
* **Запрещенные манипуляции:**
  * ❌ Разделение частей буквы S.
  * ❌ Веерные анимации синапса, ломающие внутреннюю геометрию S.
  * ❌ Прямые горизонтальные лучи.
  * ❌ Сверхбыстрая хаотичная анимация.
  * ❌ Устаревшие «техно-шрифты из 90-х».

## 3. ЦЕЛЕВАЯ ТЕХНИЧЕСКАЯ АРХИТЕКТУРА (5-LAYER MODEL) И СУБД

### 3.1. Декомпозиция 5 слоев
1. **Experience Layer:** Изолированный фронтенд на Cloudflare Workers & Pages. Дашборды, LCH, карты архитектуры.
2. **Intelligence Layer:** Оркестрация когнитивных ИИ-агентов, парсинг документов, Process Mining, AI Abstraction Gateway.
3. **Business Logic Layer:** Вычислительное ядро на Go (Golang), исполнение сценариев, калькуляция ROI, управление графом процессов To-Be.
4. **Integration Layer:** Шлюзы к 1С:ERP, CRM, SAP, СУБД, REST/gRPC API через очереди сообщений.
5. **Governance Layer:** Мониторинг безопасности, аудит доступа, деперсонализация персональных данных по ФЗ-152 РФ.

### 3.2. Архитектурные правила
* **Separability Rule:** Фронтенд и бизнес-логика отделимы. Изменение UI не затрагивает интеграционные коннекторы.
* **LLM-Agnostic Pattern:** AI Gateway позволяет на лету переключать инференс между облачными API (Yandex Cloud, GigaChat, OpenAI) и локальными Open-Source моделями (Llama, Mistral) в закрытом контуре заказчика.

### 3.3. Модель данных и СУБД (PostgreSQL + JSONB + Redis)
* **PostgreSQL RLS:** Изоляция данных клиентов в мультиарендной среде (Multi-tenancy).
* **JSONB (draft-2020-12):** Хранение графов `complexity_graphs` (узлы As-Is/To-Be, метрики ошибок, агенты).
* **Оптимизация:** GIN-индексы, временное партиционирование логов и кэширование в Redis (отклик \(\le 15\) мс).

### 3.4. Стек и CI/CD
* **GitHub:** `knyavik-stack/synapsemax`.
* **Хостинг:** Cloudflare Workers Builds.
* **Маршрутизация:** REG.RU (DNS) \(\rightarrow\) Cloudflare (Proxy) \(\rightarrow\) `synapsemax.ru`.
