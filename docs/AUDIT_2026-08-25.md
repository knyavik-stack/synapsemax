# SynapseMax — Technical / UX Audit 2026-08-25

## Executive assessment

The current prototype is visually coherent and materially closer to the accepted concept than earlier iterations. It is still a prototype, not yet a robust production-grade frontend architecture.

## Verified repository state

- Repository: `knyavik-stack/synapsemax`
- Default branch: `main`
- Current latest commit: `39b2076261a83f0178203266fb49507d4f016d35`
- Frontend is currently concentrated in a single `index.html` of roughly 57 KB.
- Assets are kept in `assets/` and include the canonical symbol, wordmark, source/reference images.
- Cloudflare deployment is already live at the Worker URL supplied by the project owner.

## Strengths

1. Canonical logo and wordmark assets are now used directly.
2. The surrounding orbital/neural animation no longer manipulates the S itself.
3. Reduced-motion support exists.
4. Scroll and pointer work is partly requestAnimationFrame-gated.
5. The page has meaningful semantic sections: solutions, cases, approach and AI Lab.
6. Responsive breakpoints exist for desktop/tablet/mobile.
7. The “Approach” visualization already expresses complexity → system instead of being purely decorative.

## Critical issues

### A1 — Monolithic frontend

Most CSS and JavaScript live in one HTML file. This is acceptable for a prototype but becomes a maintenance bottleneck as the system grows.

**Action:** migrate toward a componentized structure without changing visual output first.

### A2 — Duplicate CSS rules

The stylesheet contains repeated definitions for `.brand`, `.brand-name`, `.synapse-logo`, `.icon-box`, `.card h3`, `.section`, `.signal-grid`, and related selectors. Later declarations override earlier ones.

**Risk:** unpredictable future changes and unnecessary CSS payload.

**Action:** consolidate tokens and selectors during the architecture refactor.

### A3 — External typography dependency

The site loads Orbitron and Manrope from Google Fonts at runtime.

**Risk:** privacy/performance/network dependency and visual drift if font loading fails.

**Action:** evaluate self-hosted production fonts and define a fallback stack before public launch.

### A4 — Demo metrics presented as if factual

The current case section contains values such as `−35%`, `×2.4`, `24/7`, `−61%`, `−44%`, `+31%`, etc. There is no evidence in the current repository that these are verified customer results.

**This is the highest-priority content integrity issue.**

**Action:** until verified real cases exist, label such figures explicitly as illustrative/demo scenarios or replace them with process metrics. Never imply fictional results are customer results.

### A5 — Contact identity mismatch

The CTA uses `hello@synapsemax.ai` while the primary public domain is `synapsemax.ru`.

**Action:** confirm the actual corporate email/domain before launch; do not ship a non-existent or ambiguous contact identity.

### A6 — Architecture is not yet ready for platform evolution

The prototype embeds all presentation, content and interaction logic together. This is fine for H1 prototyping but will resist H2 features such as AI assessment, personalization, authenticated workspaces and dynamic content.

**Action:** separate content/data, UI components and service interfaces before adding platform features.

## UX / product observations

### Hero
Strong visual identity. The next improvement should focus on business clarity and conversion rather than more effects.

### Solutions
Good grid foundation. It currently communicates capabilities, but should progressively evolve toward business outcomes and transformation journeys.

### Cases
Visual system is strong. The next version must distinguish clearly between:
- verified customer cases;
- anonymized real cases;
- illustrative simulations.

### Approach
This is one of the strongest conceptual blocks. Keep the “complexity → architecture → system” model and make the transitions more explanatory.

### AI Lab
Useful as a concept demonstrator. It should not imply that the shown orchestration is already connected to a production AI backend unless it actually is.

## HUD Futuristic direction

Do not add more HUD elements indiscriminately. Build a reusable proprietary grammar:

- orbit
- node
- data rail
- callout
- scanner
- system panel
- state indicator
- neural flow
- transformation funnel

Every element needs a semantic role.

## Architecture recommendation

### Phase 1 — refactor without visual redesign

Create:

- design tokens
- component primitives
- content data layer
- animation utilities
- responsive rules
- accessibility utilities

### Phase 2 — UX architecture

Define:

- ICP
- primary user journeys
- conversion points
- content hierarchy
- CTA strategy

### Phase 3 — platform readiness

Introduce interfaces for:

- assessment API
- ROI calculation
- AI orchestration
- analytics
- CRM

Do not connect a real LLM until the business contract and data boundaries are defined.

## Pre-mortem

1. **Statistical:** illustrative metrics could be interpreted as real results and damage credibility.
2. **Architectural:** continuing to grow the monolithic HTML will make every future AI/platform feature more expensive.
3. **Performance/UX:** adding HUD effects faster than semantic content will create visual overload and reduce conversion.

## Recommended immediate sequence

1. Protect the accepted logo/wordmark.
2. Correct content integrity (demo vs verified metrics).
3. Confirm corporate contact identity.
4. Consolidate CSS and design tokens.
5. Extract reusable UI primitives.
6. Preserve the current visual result while refactoring.
7. Only then begin the next visual/UX iteration.
