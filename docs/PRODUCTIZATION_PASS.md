# SynapseMax — Productization Pass H1

**Статус:** рабочий регламент
**Дата:** 2026-08-26

## Цель

H1-сайт должен быть не обычным корпоративным лендингом, а первым коммерческим интерфейсом будущей Transformation Intelligence Platform. При этом H1 не должен притворяться готовым H2/H3 SaaS-продуктом.

## Стратегический контракт

`Complexity → Understanding → System → Automation → Outcome`

Коммерческий цикл H1:

`Diagnose → Design → Simulate → Automate → Monitor`

Эти две цепочки должны быть видны пользователю как одна логика, а не как набор независимых секций.

## Что уже есть в Immediate

- Hero и позиционирование.
- Карта сложности / проблема.
- Решения.
- Transformation Assessment.
- Complexity → System / As-Is → To-Be.
- ROI-модель.
- Пятислойная архитектура.
- Security / trust контур.
- CTA и публичный контакт.
- HUD/FUI как функциональный визуальный язык.

## Что является следующим приоритетом

### P0 — доказать единую систему

Каждый основной блок должен отвечать на три вопроса:

1. Что SynapseMax получает/понимает?
2. Что система делает с этим контекстом?
3. Какой следующий измеримый результат получает клиент?

### P1 — усилить доказательство результата

Кейсы не должны быть декоративными карточками. Минимальная модель кейса:

`Исходная проблема → процесс → вмешательство → автоматизация → метрика результата`.

Если реальных кейсов пока недостаточно, использовать честные сценарии/гипотезы и явно маркировать их как сценарии, не выдавая за клиентские результаты.

### P1 — Trust как часть продукта

Security должна объяснять архитектурный механизм:

`данные → Governance → деперсонализация → AI abstraction → модель → audit trail`.

Не использовать юридические заявления, которые нельзя подтвердить технической реализацией.

### P1 — Integrations как доказательство применимости

Показывать классы интеграций и направление обмена:

`ERP / CRM / DB / API / документы → SynapseMax → управляемое действие`.

Не обещать готовый коннектор, если он ещё не реализован.

### P2 — будущие H2-входы

Assessment, ROI, AI Consultant, Architecture Simulation и Customer Workspace должны иметь понятные точки роста, но H1 не должен имитировать полнофункциональный SaaS.

## Definition of Done для Productization Pass

- За ~15 секунд понятно, что SynapseMax делает с бизнес-сложностью.
- CTA связан с диагностикой, а не просто с контактом.
- Assessment является входом в transformation journey.
- ROI связан с конкретным процессом/гипотезой.
- Architecture объясняет связь данных, интеллекта, действий и контроля.
- Каждый HUD-элемент имеет информационную функцию.
- Нет выдуманных клиентских кейсов или неподтверждённых технических обещаний.
- Mobile сохраняет смысловую плотность без микротекста.
- Визуальная система не превращается в cyberpunk-декорацию.

## Архитектурное ограничение

Frontend H1 остаётся совместимым с будущими Experience / Intelligence / Business Logic / Integration / Governance слоями. Нельзя зашивать будущую бизнес-логику или зависимость от конкретной LLM непосредственно в UI.
